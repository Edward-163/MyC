硬件中断
系统运行时,外部io收到事件,通过中断通知cpu处理,cpu收到中断,打断当前运行的任务(非中断关闭),调用对应中断服务程序,执行完后返回中断地方继续执行

软锁
softlockup is defined as a but that causes the kernel to loop in kernel mode for more than 20s,without giving other tasks to run
代码运行在内核态超过一定时间,触发;内核调度停滞。CPU 还在执行代码，但调度器无法让其他任务运行
常见于
频繁处理硬中断,cpu核没时间去调度
长时间处理软中断
非抢占式内核,线程长时间执行且不主动触发调度

软狗
因为软锁,cpu核执行任务A且不调度,软狗的机制是内核喂狗线程(高优先级percpu内核线程watchdog/n)定时唤醒喂狗,它不被cpu调度,无法执行,喂狗超时

硬锁
hardlock is defined as a bug that causes the cpu to loop in kernel mode for more than 10s,without letting other interrupts to run
内核代码长时间关闭中断

硬狗 NMI狗  附:nmi中断==non Maskable interrupt不可屏蔽的中断
由于普通中断被屏蔽，高精度定时器（hrtimer(依赖于中断（通常是时钟中断或模拟定时器事件）来触发)）也可能无法工作。因此，内核使用了更底层的 NMI (Non-Maskable Interrupt，不可屏蔽中断)。
NMI 是最高优先级的中断，几乎无法被屏蔽。系统会周期性地（默认每10秒）通过 NMI 触发一个 Perf 事件来检查。如果连续两次检查都发现 CPU 没有响应，就判定发生了
当系统进入 Hardlockup 状态时，意味着 CPU 卡死在了某个关闭了中断的代码路径上（比如在驱动程序的 spin_lock_irqsave 区间内死循环，或者在中断处理函数本身中卡住了，因为中断处理函数默认就是关中断的

RIP是x86_64架构下的指令指针寄存器（Instruction Pointer），指向当前正在执行的指令地址。在Linux内核崩溃信息或日志中，RIP行通常显示导致问题的那条指令所在的函数以及偏移量。它提供了问题发生的确切位置，是定位问题的起点
RIP: 0010:try_to_wake_up+0x40/0x4c0
+0x40：指令在函数内部的偏移量，即从函数起始地址往后数 0x40 个字节
/0x4c0：函数的总大小（字节数，十六进制），这里表示 try_to_wake_up 函数共有 0x4c0 字节（约 1216 字节
